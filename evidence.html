Benchmark specification

The primary objective is disciplined reserve-aware accumulation behavior, not a price forecast. Equal-capital alternatives must be specified before public timing claims are strengthened.

Current boundary

  • Current forward record: no reserve deployment has occurred.
  • Current public reserve balance: zero public-policy daily units unless the summary says otherwise.
  • Current spread: no demonstrated timing advantage when BTC Helper and fixed DCA have not diverged.
  • Track is process evidence and governance evidence; it is not efficacy proof.

Comparison program

  • Primary objective: compare disciplined accumulation behavior, not short-term price prediction.
  • Gap handling: degraded runs and missing publication dates must be visible and benchmark claims must be withheld or qualified.
  • Fixed DCA: ordinary recurring accumulation with the same public daily budget.
  • Seeded reserve: equal-capital reserve account available before the test window.
  • Reserve yield: optional cash/T-bill-style yield or cash-drag accounting for reserve balances.
  • Calendar deployment: equal-capital reserve deployed on fixed dates regardless of BTC Helper.
  • Simple drawdown rule: reserve deployed on mechanical drawdown triggers.
  • Valuation-only rule: reserve behavior driven by a single valuation-state proxy.
  • Matched random deployment: random reserve events matched to the observed number of BTC Helper reserve events.
  • Frozen BTC Helper policy: a locked public policy version evaluated prospectively before any methodology change.

Benchmark rules and degraded-day boundaries are documented in the methodology.

Public evidence protocol

Evidence is deliberately split into observed forward reads, replay artifacts, and evidence bundles. The latest forward read has a public-safe grounded reconstruction bundle because the source audit was captured before publication but the bundle record was assembled later; older reads and replay artifacts keep their own provenance labels, so the public record is useful today but still not yet a complete evidence audit.

  • Bundle ID and content hash
  • Decision timestamp and methodology version
  • Source as-of timestamp, retrieval timestamp, and expected frequency
  • Frequency-aware freshness and degraded/unavailable state
  • Transformation/schema version used for public normalization
  • Fallback, stale, imported, or manually reviewed status
  • Correction/revision status and provenance label

Normalized factor-state boundary

Factor states and directions can be published as normalized labels where the public data model retains them. Raw values, thresholds, weights, and override rules stay private.

  • Current public factor states and directions can be shown when retained source-run history supports them.
  • Older daily permalinks may not reconstruct factor-level snapshots if the historical public record did not retain them.
  • Factor states are normalized public labels, not raw metric values or exposed thresholds.
  • Evidence-bundle v1 preserves the latest factor-state record with source timestamps and transformation version labels.

Evidence methodology and replay boundaries are documented on the methodology page. Each build checks that the latest live chart marker and visible latest-read BTC price come from the same public-history record.

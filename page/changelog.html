Product history

Changelog

Public-facing BTC Helper product and methodology changes, written for visitors who want to understand what changed over time.

2026-07-20: Homepage returning-plan simplification

Added a saved-plan homepage mode that shows a compact welcome-back summary when a visitor has a local plan in this browser.

Hid first-visit explanatory content for returning planners so the homepage starts closer to today’s useful decision context.

Moved factor movement and audit detail behind one control so the Today section stays shorter while preserving the underlying record.

2026-07-20: Household planner plain-language lead

Updated the full Household Resilience Planner so its result starts with plan durability, main pressure, resilience floor, optional accumulation room, and first next step.

Moved the resilience score, ratios, and score breakdown behind a supporting-detail control so the page no longer leads with false precision.

Added public checks so future builds keep the planner plain-language first.

2026-07-20: Updates delivery clarity

Changed the Updates page to state plainly whether RSS, waitlist fallback, or double opt-in email delivery is active.

Reframed the email form around behavior-changing alerts, source-health changes, weekly summaries, and monthly plan review.

Removed implementation-language details from the public Updates page so readers do not need to understand collection or delivery plumbing.

2026-07-20: Weekly macro template upgrade

Upgraded the weekly macro thesis article and index templates with a fuller BTC Helper shell, skip link, author line, reading time, article context table, and structured data.

Added clearer weekly sections for one-sentence thesis, changed conditions, daily-factor impact, plan implication, watch items, and confidence limitations.

Extended public checks so weekly macro pages keep protected source details out while preserving accessibility coverage.

2026-07-20: Source-health transparency polish

Updated Source health to name public provider/source families, expected cadence, source as-of status, retrieval date, coverage domains, and known limitations.

Grouped current sources by provider/source family so shared providers appear once instead of repeated internal field rows.

Kept source links, raw metric values, exact field mapping, thresholds, weights, override rules, calibration details, and private validation notes outside the public surface.

Added public checks that keep provider names out of weekly macro and main decision surfaces while preventing implementation-language details from appearing publicly.

2026-07-20: Track simplification

Changed Track into a forward-record-first hub with separate sections for behavior audit, audit lab, and source health.

Moved the full replay chart and case list out of the default Track flow and kept them on the Evidence page for deep readers.

Changed the top evidence framing to emphasize forward reads and replayed historical cases, while keeping candidate and synthetic counts inside Audit Lab.

2026-07-20: My Plan usability pass

Changed My Plan from one dense form into a staged flow for resilience floor, baseline, optional reserve, and control boundary.

Separated market-review and plan-review copy so visitors are not pushed toward daily checking when their plan does not need attention.

Renamed the local 30-read tracker as a hypothetical plan replay and clarified that it is not a record of confirmed purchases.

2026-07-20: Clarity and action semantics

Separated the daily output into scheduled-baseline and optional-reserve instructions before showing market context.

Changed Track metrics so plan-translation changes are no longer presented as behavior-changing events.

Simplified the homepage flow by moving local-plan preview ahead of sharing tools and reducing repeated watchlist copy.

2026-07-20: Validation governance alignment

Updated Track and methodology to show current replay-evidence tiers at a high level: replayed, grounded candidate, candidate, and synthetic cases.

Added clearer language separating project-level replay artifacts from mature performance backtest proof.

Kept raw metrics, thresholds, weights, calibration details, source links, and private validation notes outside the public surface.

2026-07-20: Operator disclosure

Updated the About page to name Arne Kotte as the operator of BTC Helper.

Clarified that BTC Helper is an independent educational research project and does not provide individualized financial advice, execute trades, custody assets, or receive exchange/referral compensation.

2026-07-19: Model-quality dashboard

Added a Track dashboard for methodology versioning, forward-read count, plan-translation changes, source-health distribution, coverage distribution, missing expected dates, and current validation priorities.

Separated model governance from performance claims by presenting known limitations next to the public record and behavior audit.

Clarified that provider/source families are public while direct source links, raw inputs, thresholds, weights, overrides, and calibration details remain outside the public dashboard.

2026-07-19: Event-driven update preferences

Reworked the updates page around meaningful-change delivery: behavior-changing alerts, material source-health changes, weekly macro context, and optional monthly plan-review reminders.

Added delivery-status cards, explicit no daily no-change emails policy, and a local preference preview before the update-interest request is sent or converted into a prefilled email.

Updated the private update-interest intake path to preserve selected alert preferences while keeping planner and household values out of the payload.

2026-07-19: Product architecture and weekly insights

Reframed the public site around one accumulation journey: Today, My Plan, Insights, and Track.

Added an Insights landing page for weekly macro context, selected research, and factor explainers.

Added a Track route for the public record, behavior audit, source health, and replay/audit boundaries while keeping the prior evidence route available.

Changed the primary posture language toward practical plan translations such as Baseline only, Scheduled plan unchanged, optional reserve review, and Hold optional allocation.

Updated planner copy so baseline accumulation and optional reserve are separated more clearly, with budget and reserve values remaining local to the visitor browser.

2026-07-13: Retention, factor movement, and public-boundary cleanup

Added factor-level movement rows so returning visitors can see valuation, holder behavior, flows, macro pressure, leverage, data quality, and posture movement even when the headline stance remains unchanged.

Added a redacted public source-audit snapshot for the latest daily read when a full source report is available. It shows source freshness and factor states without publishing raw metric values, exact field mix, thresholds, weights, override rules, or calibration details.

Made publication gaps explicit in the archive so missing expected read dates are visible instead of silently omitted.

Aligned the research-library and household-planner header/footer shell with the core BTC Helper navigation.

Expanded privacy-light engagement events for planner starts, saves, tab use, examples, and CSV downloads without collecting planner dollar amounts or personal financial details.

Updated the updates page with the intended alert policy: posture changes, material source-health changes, and weekly summaries for underlying condition movement.

2026-07-13: Quality gates and archive overview

Added browser-level accessibility and interaction checks for the public surface, including skip-link behavior, mobile navigation, theme toggle, planner tabs, archive filters, update-interest form, and replay markers.

Added lightweight page-size and local load-timing budgets to keep the public surface from becoming too heavy.

Added archive overview bars and a month-by-month table so visitors can scan posture mix, data quality, and read history without relying only on the long archive log.

2026-07-13: Update interest path

Added an optional no-fee update-interest form on the updates page. By default it falls back to a prefilled email request rather than sending remote tracking events.

Updated privacy language to describe the public site default: no remote analytics endpoint unless explicitly configured.

2026-07-13: Search and metadata

Added plain-language education pages for cautious Bitcoin accumulation, DCA versus reserve-aware accumulation, and data quality in Bitcoin indicators.

Added richer metadata, daily-read structured data, RSS, sitemap entries, and static accessibility checks.

2026-07-12: Action-led redesign

Reworked the homepage around the practical buying action first, with the posture label second and evidence third.

Added daily-read permalinks, RSS, archive filters, data-sources and freshness notes, About, Privacy, and Terms pages.

Added a verified structural valuation anchor as a real valuation input while keeping exact calibration details private.

How to read this changelog

This changelog is about the public website, methodology communication, source transparency, and user experience. It is not a trade log and does not replace the dated daily-read archive.

BTC Helper remains an educational planning tool. Product changes are meant to make the daily stance easier to understand, not to imply price prediction certainty.

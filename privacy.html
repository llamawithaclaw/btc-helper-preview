Local-first design

Privacy

BTC Helper is designed to avoid collecting personal financial details from the public site.

Planner data

The manual planner runs in the browser. Budget, cadence, reserve rule, protected-cash buckets, optional reserve, theme preference, and similar settings stay on the visitor device unless the visitor exports them manually.

Planner profiles can be saved locally in this browser or used for the current browser session only. Local browser profiles are not encrypted by BTC Helper, and some browsers may sync local browser storage through the user's own browser account. Shared-device users should choose session-only mode or use Clear this device when finished.

Clear this device removes the BTC Helper planner profile and planner visit marker stored by this site in the current browser. It does not clear browser sync copies, screenshots, downloads, email records, or data a visitor separately saved outside BTC Helper.

Those values are not sent to BTC Helper by the static public site.

Analytics

By default, no remote analytics endpoint is configured. When no endpoint is configured, interaction events remain local to the browser for debugging only.

If a privacy-light analytics endpoint is configured later, the intended event payload is limited to event name, page path, link text or href, coarse workflow categories, timestamp, and build timestamp. It should not include budget amounts, suggested buys, reserve values, planner dollar values, imported files, cookies, IP retention, or cross-site identifiers.

Update requests

The update-interest form can collect an email address, selected alert preferences, no-change email preference, source page path, site identifier, and public build timestamp if the first-party email API is configured. Without an endpoint, it opens a prefilled email request instead.

Email requests are for BTC Helper action-change alerts, source-health alerts, weekly summaries, or optional monthly plan-review reminders. They are separate from planner data and should not be mixed with financial inputs.

Live email updates use a first-party Cloudflare Worker at the BTC Helper API domain, Cloudflare D1 for subscriber records, and Resend for sending email from the verified btchelper.app domain. Confirmation is double opt-in before an address becomes active.

Subscriber records may include email address, normalized email address, pending/confirmed/unsubscribed status, selected preferences, request type, no-change policy, source path, site identifier, build timestamp, confirmation time, unsubscribe time, hashed confirmation/unsubscribe tokens, and delivery metadata such as sent or dry-run records.

Confirmation and unsubscribe tokens are stored as hashes rather than raw one-time tokens. Recurring weekly emails include unsubscribe links plus List-Unsubscribe and one-click unsubscribe headers.

The update form and email Worker do not collect planner budgets, household inputs, reserve balances, purchase amounts, cookies, or cross-site identifiers. Planner and household values are not stored in the email subscriber record.

Cloudflare and Resend may process ordinary service, security, and delivery metadata, including IP addresses transiently, as part of receiving requests and sending email. Current project code does not add an email open-tracking pixel or click-tracking redirect, but provider/account-level tracking settings, retention/deletion rules, and subprocessors should be confirmed during external privacy/legal review.

Public artifacts

The public site exposes only public-facing BTC Helper artifacts: daily reads, source notes, RSS, CSV, share card, documents, and research pages.

Private metrics CSV tokens, private service paths, and local environment files are not part of the public surface.

Private live-validation records are internal model/publication records, not stored user planner financial profiles.

Retention and deletion

Public daily records, source snapshots, research pages, and correction history are intended to remain public so the record is auditable.

Planner data is deleted by using session-only mode, Clear this device, or the browser's own site-data controls. Email and support records are handled separately from planner data and should be reviewed under the email/compliance process before commercialization.
